# GoldBot — сигналы по XAUUSD (M5)

Бот подключается к запущенному терминалу MetaTrader 5, берёт котировки золота,
ищет сетапы на закрытых барах M5 и пишет в консоль готовый сигнал:

- направление (BUY/SELL);
- цену входа;
- стоп-лосс и тейк-профит;
- расстояние до стопа и риск по цене;
- причину сделки и уверенность;
- максимальное время удержания.

Сделки бот **не открывает** — только сигналит. Все сигналы сохраняются в
`data/signals.csv`, и бот сам отслеживает, чем они закончились (TP / SL / выход
по времени), чтобы вы видели реальную статистику, а не только красивый бэктест.
Сигналы и результаты можно получать в Telegram (см. ниже).

равно будут — это нормально.

## Требования

- Windows (MetaTrader5 Python API работает только на Windows).
- Установленный и **запущенный** терминал MetaTrader 5, вход в счёт.
- Python 3.10+ (проверено на 3.13).
- Символ `XAUUSD` добавлен в Market Watch.

## Установка

```bat
pip install -r requirements.txt
```

Проверка связи и текущего состояния:

```bat
python run_live.py --once
```

## Запуск

Постоянный режим (ждёт закрытия каждого бара M5):

```bat
python run_live.py
```

Или двойным кликом по `start_bot.bat`.

Бэктест:

```bat
python run_backtest.py
python run_backtest.py --refresh          :: заново скачать историю
python run_backtest.py --tune             :: проверить устойчивость параметров
python run_backtest.py --realistic        :: жёсткие условия: open(i+1) + 5 пт + спред 21
python run_backtest.py --start 2026-01-01 --end 2026-11-01
```

`--realistic` — стресс-проверка исполнения: сигнал на закрытии бара, вход по
открытию следующего бара, проскальзывание 5 пунктов против сделки, спред в 21
пункт. Результаты пишутся в `reports/backtest_realistic_*`, обычные файлы
`reports/backtest_*` не перезаписываются. Отдельно можно задать
`--slippage N` и `--spread N`.

Результаты бэктеста сохраняются в `reports/`.

## Автоторговля (исполнитель сигналов)

Два независимых процесса, две консоли:

```bat
:: окно 1 — анализатор, он же сигналы в Telegram
python run_live.py

:: окно 2 — исполнитель, он же сделки на счёте MT5
python run_executor.py
```

Или двойными кликами: `start_bot.bat` и `start_executor.bat`.

### Анализатор без Telegram

Если сигналы в Telegram уже шлёт другой бот (например, у заказчика), а здесь
нужен только источник сигналов для исполнителя, запустите анализатор с флагом:

```bat
python run_live.py --no-telegram
```

Или двойным кликом по `start_bot_no_telegram.bat`. Сигналы по-прежнему пишутся
в `data/signals.csv` и закрываются в журнале, исполнитель работает как обычно,
но в Telegram не уходит ничего: ни сигналы, ни результаты, ни сообщение о
запуске, и бот не читает команды. В шапке будет строка
`Telegram: выключен (--no-telegram) — сигналы только в журнал`.

### Статистика в карточке сигнала

Внизу заголовка карточки две пары строк:

```
🔴 SELL  XAUUSD M5 — Провал пробоя (вечер, продажа)

Статистика за 7 дней:
3 / 66.7% / вытеснено 1
Статистика за 14 дней:
6 / 66.7% / вытеснено 1
```

Числа через `/`: сделок за окно / винрейт / сколько сигналов не взяли, потому
что уже была открыта другая сделка (бот держит одну позицию за раз).

Считается при запуске анализатора и обновляется раз в сутки. Вручную:

```bat
python run_monitor.py --stats
```

Пишет `data/setup_stats.json` и печатает те же числа в консоль.

Анализатор ничего не знает про сделки: он пишет сигналы в `data/signals.csv`.
Исполнитель читает этот файл, видит новый сигнал и открывает рыночный ордер
с SL и TP из сигнала. Дальше позицию ведёт брокер — исполнитель её не трогает.

Настройки в `config.json`:

```json
"execution": {
  "enabled": true,
  "symbol": "XAUUSD",
  "lot": 0.01,
  "magic": 770001,
  "server": "",
  "terminal_path": "",
  "max_positions": 1,
  "max_signal_age_minutes": 3,
  "max_entry_slip_points": 100,
  "deviation_points": 20,
  "poll_seconds": 2,
  "state_path": "data/executor.csv",
  "log_path": "data/executor.log"
}
```

- **`lot`** — лот по умолчанию. Исполнитель спрашивает его при запуске
  (`Лот (Enter — 0.01):`), так что вписать можно прямо в консоли, а Enter
  оставит значение из конфига. Риск в деньгах = `risk_price × 100 × lot`.
  При лоте 0.01 и SL 6 $ это 6 $.
- Лот можно поменять и на ходу: исправьте `execution.lot` в `config.json` —
  исполнитель подхватит новое значение в течение пары секунд, перезапуск не
  нужен. В консоли появится строка `лот изменён: 0.01 -> 0.02`.
- `max_positions` — сколько позиций держать одновременно (1 = как в бэктесте).
- `max_signal_age_minutes` — сигналы старше этого возраста не исполняются
  (защита от запуска посреди дня со старым журналом).
- `max_entry_slip_points` — если цена ушла от сигнальной дальше, сделка
  пропускается (обычно спред 13–21 пт, лимит 100 пт = 1 $ на золоте).
- `magic` — метка своих позиций; по ней исполнитель находит их после
  перезапуска и не путает с ручными сделками.
- `server` и `terminal_path` — необязательные значения по умолчанию для входа
  в счёт и поиска терминала.

### Вход в свой счёт

Исполнитель не привязывается к тому счёту, который случайно открыт в
терминале. При запуске он спрашивает:

```
Вход в торговый счёт MT5
  Enter без логина — использовать счёт, открытый в терминале.
Логин MT5: 12345678
Пароль MT5 (ввод не отображается):
Сервер [MetaQuotes-Demo]:
Запомнить в data/account.json? (y/n):
```

- **Enter без логина** — работать со счётом, в который залогинен терминал
  (прежнее поведение).
- Пароль при вводе не отображается.
- Если ответить `y`, логин/пароль/сервер сохранятся в `data/account.json`,
  и следующий запуск войдёт в счёт сам. Файл хранит пароль **в открытом
  виде** — не передавайте его никому и не выкладывайте в публичный репозиторий.
- Сменить счёт: `python run_executor.py --forget` и запустить заново.
- Без вопросов (для автоматизации):
  `python run_executor.py --login 12345678 --server MetaQuotes-Demo`
  (пароль спросит в консоли; `--password` тоже есть, но он останется в
  истории команд).

Если `data/account.json` существует, его же использует и анализатор
(`run_live.py`) — оба процесса работают с одним счётом. Терминал MT5 умеет
быть залогинен только в один счёт одновременно, поэтому это единственный
непротиворечивый вариант.

Ошибка входа не роняет процесс молча: исполнитель печатает причину и
выходит. Вход ограничен 20 секундами — при неверном имени сервера
терминал иначе может висеть минутами.

Что исполнитель пишет:

| файл | содержимое |
|---|---|
| `data/executor.csv` | все сделки: тикет, цена входа, SL/TP, результат в $ и R |
| `data/executor.log` | лог: открытия, закрытия, пропуски и причины |

Проверить без отправки ордеров:

```bat
python run_executor.py --dry-run --once
python run_executor.py --once
python run_executor.py --lot 0.02
python run_executor.py --slip 2
```

`--dry-run` прогоняет заявку через `order_check` и пишет `[DRY]` в лог, но
ничего не отправляет. `--once` делает один проход и выходит. `--lot` задаёт
лот на запуск, не меняя `config.json`.

`--slip` — лимит ухода цены от сигнала в долларах (по умолчанию 1). Если
пришёл сигнал на покупку, а цена уже ушла на 2 $ вверх, сделка пропускается.
Без флага значение спрашивается в консоли при запуске (Enter — оставить
текущее); введённое число запоминается в `config.json` →
`execution.max_entry_slip_price`.

Важно: `execution.enabled` и `lot` читаются **при старте** исполнителя.
Изменили лот — перезапустите окно исполнителя.

## Telegram-уведомления

Бот рассылает сигналы **нескольким людям**, но доступ — только по белому
списку. Пока человека нет в списке, бот **полностью игнорирует** его сообщения
и ничего ему не присылает. Никаких заявок и кнопок «разрешить/отклонить» нет.

### Первый запуск

1. Откройте бота **https://t.me/mysiggnalsbot** и нажмите **Start**.
2. Привяжите **администратора** (скрипт ждёт сообщение до 2 минут):

   ```bat
   python telegram_setup.py --wait 120
   ```

   Скрипт найдёт ваш `chat_id`, сохранит его в `config.json`, добавит вас
   в базу и отправит тестовое сообщение. Запускайте при остановленном
   live-боте: иначе он тоже читает сообщения.
3. Проверка в любой момент:

   ```bat
   python telegram_setup.py --test
   ```

### Как добавить человека

1. Человек пишет боту любое сообщение (например `/start`). Бот **молча**
   запоминает его ID и username и не отвечает.
2. Администратор выдаёт доступ:
   - по числовому ID: `/allow 123456789`
   - по username: `/allow @nick` — только если человек уже писал боту.
     Telegram не позволяет узнать ID по username до первого контакта.

   Если добавить по ID человека, который ещё не нажимал Start, он начнёт
   получать сигналы только после первого сообщения боту: Telegram не даёт
   ботам писать незнакомым пользователям первыми.
3. Человек получает уведомление и начинает получать сигналы. При первом
   `/start` бот один раз спрашивает язык кнопками; позже язык меняется
   командой `/lang` или кнопкой **Lang**.

Внизу чата у пользователя появляется постоянная клавиатура
**Start · Stop · Lang · TF** — это те же команды `/start`, `/stop`, `/lang`,
`/tf`. У администратора в личке есть ещё кнопка **Channels** (`/channels`).

### Команды

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | с доступом | включить сигналы |
| `/stop` | с доступом | отключить сигналы |
| `/lang` | с доступом | сменить язык (кнопки) |
| `/tf` | с доступом | какие отчёты присылать лично: 5/15/30/60 мин или все |
| `Start` · `Stop` · `Lang` · `TF` | с доступом | кнопки нижней клавиатуры |
| `/users` | админ | список пользователей и статусов |
| `/allow <id\|@username>` | админ | выдать доступ |
| `/deny <id\|@username>` | админ | отозвать доступ |
| `/remove <id\|@username>` | админ | удалить из базы |
| `/channels` | админ | список каналов (есть кнопка **Channels**) |
| `/channel ...` | админ | настройка канала |

Статусы: ✅ активен, ⏸ приостановлен, 🚫 нет доступа.

Пользователи хранятся в **SQLite**: `data/goldbot.db`. Старый
`data/subscribers.json` один раз переносится в базу автоматически при первом
запуске. Админ из `config.json` → `telegram.chat_id` всегда активен и не может
быть удалён из бота.

Сообщение о запуске получает **только администратор**; номера счёта и баланса
в нём нет. Отключается через `"notify_startup": false`.

> **Безопасность.** Токен бота хранится в `config.json` открытым текстом.
> Не публикуйте этот файл и не пересылайте его. Если токен попал в чужие руки,
> перевыпустите его у @BotFather (`/revoke`).

## Логика стратегии

В конфиге 14 сетапов, включены 9. Отключены: `sell_noon` (живьём одни
минусы: выход по времени не исполняется), `dip_late` (минус на 7/14/30 днях),
`rsi_ny`, `stretch_ny`, `short_rally_london`.

| сетап | напр. | когда | вход |
|---|---|---|---|
| `dip_london` | BUY | 09–15 | падение 2.5 ATR за 4 бара |
| `sell_break` | SELL | 12–18 | пробой 7 баров вниз + M15 вниз |
| `swing_high` | SELL | 09–18 | хай + RSI ≥ 55 + M15 вниз |
| `pullback_cross` | BUY | 09–18 | возврат выше EMA10 + M15 вверх |
| `keltner` | SELL | 09–18 | close выше EMA20 + 2 ATR, медвежий бар |
| `fade_late` | SELL | 15–20 | ложный пробой 12 баров |
| `evening_break` | SELL | 20–22 | пробой 12 баров + M15 вниз |
| `zone_bounce_buy` | BUY | 00–22 | отбой от поддержки + M15 вверх |
| `zone_bounce_sell` | SELL | 00–22 | отбой от сопротивления + M15 вниз |

### Зонный отбой (`zone_bounce_buy` / `zone_bounce_sell`)

Торгует те же уровни, что рисует отчёт по уровням (`goldbot/zones.py`).

- Зоны считаются по окну последних **24 часов** (288 баров M5), по закрытым
  барам — заглядывания вперёд нет.
- Берутся только зоны с **2+ касаниями** и силой **strong / strongest**.
- Вход: цена коснулась зоны (в пределах 0.25 ATR) и закрылась обратно,
  бар в сторону отбоя. Плюс фильтр тренда **M15** (EMA50/EMA200).
- Стоп: за зону на 0.15 ATR (или за swing, что дальше).
- Тейк: на следующей противоположной зоне; если она ближе 0.8R — 1R.
- Выход по времени: 24 бара. После 22:00 новых входов нет.

Результат при 0.01 лота: 7 дней — buy +1.6R, sell +2.1R; 14 дней — buy +0.6R,
sell +12.6R. Без фильтра M15 тот же отбой уходит в минус, поэтому фильтр
обязателен.

### Почему часть сетапов выключена

- `sell_noon` — в бэктесте плюс, но он держится на выходе через 6 баров
  (12 из 18 сделок закрываются по времени). Исполнитель закрывать по времени
  не умеет, поэтому живьём обе сделки ушли в SL: −7.71$ и −8.82$.
- `dip_late` — минус на всех окнах: 7д −3.1R, 14д −2.3R, 30д −1.4R.
- `rsi_ny`, `stretch_ny` — минус на 30 днях (−5.7R и −7.4R).
- `short_rally_london` — около нуля, преимущества нет.

### Общие фильтры

- Спред не больше **30 пунктов**.
- Расстояние до стопа не больше **$12 по цене** (1200 пунктов) — защита от
  сделок с огромным SL в высокой волатильности.
- Лот **не фиксирован**: размер позиции вы выбираете сами. Риск в долларах =
  расстояние до SL × 100 × ваш лот (например, 0.10 лота и SL $7 = $70).
- Пауза 6 баров после закрытия предыдущей сделки.
- Лимит 50 сигналов в день — фактически выключен: при одной позиции и паузе
  6 баров больше ~10–12 в день не выходит. Оставлен как страховка от зацикливания.
- Одновременно только один активный сигнал.

Приоритет при совпадении условий — порядок сетапов в `config.json`:
если в один бар сработали два, бот выдаёт тот, что записан выше.

## Настройки (`config.json`)

| Параметр | Что означает |
|---|---|
| `symbol`, `timeframe` | Инструмент и таймфрейм (по умолчанию XAUUSD M5). |
| `max_spread_points` | Максимальный спред в пунктах. |
| `max_risk_price` | Максимальное расстояние до стопа в $ по цене (не зависит от лота). 0 = выключено. |
| `backtest.reference_lot` | Лот только для пересчёта исторических R в доллары; на сигналы не влияет. |

## Журнал сигналов

Файл `data/signals.csv` (открывается в Excel). Колонки:

- `status` — `OPEN` или `CLOSED`;
- `exit_reason` — `TP`, `SL`, `BE`, `TIME`;
- `result_r`, `result_usd` — результат в R и долларах;
- `bars_held` — сколько баров длилась сделка;
- `mfe` — максимальная цена в пользу сделки за всё время удержания (максимум
  `high` для BUY, минимум `low` для SELL);
- `gap_to_tp` — насколько максимум цены не дошёл до тейка в долларах.
  Положительное число — недолёт (например `1.00` = цена остановилась в
  долларе от TP). Отрицательное — прокол, тейк взят с запасом;
- `exit_bar_peak` — максимум цены (для BUY) / минимум (для SELL) в том баре,
  где сделка закрылась. Для `TP` это пик свечи, на которой сработал тейк;
- `reasons` — причины входа.

Бот определяет тейк и стоп **по экстремуму свечи** (`high`/`low`), а не по
закрытию, — так же, как это происходит на реальном счёте. Поэтому прокол TP
засчитывается как TP, даже если свеча закрылась ниже.

Бот обновляет журнал по мере поступления новых баров. Это **гипотетический**
результат по цене сигнала, без учёта реального проскальзывания и комиссии
брокера.

Посмотреть статистику журнала:

```bat
python journal_stats.py
```

## Ограничения и риски

1. **Нет гарантии прибыли.** За последние 30 дней — 113 сделок, 69.9% винрейта,
   +69.4R. Выборка маленькая: на другом рынке или режиме волатильности результат
   может отличаться. Максимальная серия убытков на истории — 8 сделок подряд.
2. Направления не сбалансированы: включено 3 BUY (`dip_london`,
   `pullback_cross`, `zone_bounce_buy`) и 6 SELL (`sell_break`, `swing_high`,
   `keltner`, `fade_late`, `evening_break`, `zone_bounce_sell`). В растущем
   рынке SELL-часть работает хуже — следите за ней в журнале.
3. Нет новостного фильтра. В моменты NFP/CPI/FOMC спред расширяется, возможны
   проскальзывания. Фильтр по спреду помогает, но не спасает полностью.
4. Бэктест не учитывает комиссию брокера, свопы и проскальзывание; учтён
   только спред. Плюс бэктест закрывает часть сделок по времени (`TIME`),
   а исполнитель этого пока не умеет — живьём такие сделки идут до SL/TP.
5. Данные MetaQuotes-Demo могут отличаться от котировок вашего брокера.
6. Бот не торгует сам. Если вы не успели войти по сигналу — цена уже другая.
7. **Сигналы по уровням приходят редко.** `zone_bounce_buy` /
   `zone_bounce_sell` требуют касания сильной зоны и совпадения тренда M15 —
   это в среднем 1–3 сигнала в день на оба сетапа, иногда ноль.
8. `sell_break` в сильный тренд вниз может дать несколько сигналов подряд,
   но пауза 6 баров и правило «одна позиция за раз» срезают большинство.
   Он держится на трендовом фильтре: если EMA50/EMA200 перестанет разделять
   режимы, сетап стоит выключить.
9. Размер лота вы выбираете сами; бот не знает ваш риск в долларах. Считайте
   его как расстояние до SL × 100 × лот.

**Рекомендация:** неделю-две погоняйте на демо, сравните журнал с реальными
ценами, и только потом думайте о реальном счёте.

## Отчёт по уровням (зоны + bias)

Отдельный процесс: отправляет в Telegram разбор за 24 часа — свечной график
с зонами, bias, ближайшие уровни и план. Торговых сигналов не даёт и в
сделках не участвует.

Периодичность — **5, 15, 30 и 60 минут** (`hourly.intervals`). Цикл
просыпается на самом коротком интервале, а на каждом слоте решает, какие
отправки наступили. Что получает конкретный канал — задаётся в личке админа
(`/channel <id> 5 30`). Если каналу включены и 5, и 60 минут, в :01 он
получит одно сообщение (часовое), а не два подряд.

```
python run_hourly.py --once --no-telegram   # проверить в консоли
python run_hourly.py --once                 # отправить один отчёт всем
python run_hourly.py --loop                 # по расписанию из конфига
python run_hourly.py --loop --intervals 5,15,30,60
python run_hourly.py --loop --intervals 15 --minute 5   # :05, :20, :35, :50
python run_hourly.py --once --to admin      # только в чат админа
```

Флаги: `--hours 24` (окно анализа), `--intervals` (5,15,30,60), `--minute`
(сдвиг слота внутри часа), `--lang ru|az`, `--to all|admin`, `--csv
data/XAUUSD_M5.csv` (без MT5), `--chart-dir` (куда сохранять картинки).
Картинки старше 7 дней удаляются автоматически.

Окно анализа всегда 24 часа — зоны не скачут между 5-минутным и часовым
отчётом.

### Свечи и сильные точки

В конце каждого отчёта идёт блок по свечам того же масштаба, что и отчёт:

| Отчёт | ТФ блока | Свечей в блоке |
|---|---|---|
| 5 мин | M5 | 1 (последняя) |
| 15 мин | M15 | 2–4 активные |
| 30 мин | M30 | до 6 активных |
| 60 мин | H1 | 1 (последняя) |

Для 15 и 30 минут показываются не просто последние свечи, а те, к которым
цена реально возвращалась. Если активных меньше — блок короче, но последняя
свеча есть всегда.

```
🕯 M30 — 5 свечей
№1 · хай 3528.02 — 5 кас. · лоу 3512.57 — 1 кас.
№2 · хай 3522.80 — 5 кас. · лоу 3514.04 — 1 кас.
...

Сильные точки:
🔴 3532.06 — 9 кас. · сильная зона на SELL
🟢 3522.80 — 5 кас. · сильная зона на BUY
```

Как считается: M5-бары сворачиваются в свечи нужного ТФ, затем для каждой
свечи берутся её хай и лоу и считается, сколько раз цена подходила к уровню
и отходила от него. Касание — подход ближе `touch_tol_points` (по умолчанию
15 пунктов = 0.15 $), отход — уход от уровня на `touch_gap_points`
(50 пунктов = 0.50 $). Подряд идущие бары у уровня не считаются десятком
касаний: нужно именно отойти и вернуться.

Сильные точки — это те же хаи/лоу, но сгруппированные по цене: близкие
уровни (в пределах двух допусков) складываются в один, и если суммарно
набралось 3+ касания, точка попадает в блок. Сторона определяется просто:
выше текущей цены — SELL, ниже — BUY. Это подсказка, где цену уже
отталкивали, а не сигнал на вход.

**Кому и на каком языке.** По умолчанию (`to: "all"`) отчёт уходит каждому
активному подписчику на его языке — у кого выбран az, тот получает
азербайджанский текст и азербайджанскую картинку, у кого ru — русские.
Картинка рисуется один раз на язык, а не на человека. `--to admin` —
только в чат из `telegram.chat_id`, на языке `hourly.lang`.

**Свой интервал в личке.** Каждый может выбрать, какие отчёты получать
лично: команда `/tf` или кнопка **TF** внизу чата. Бот покажет кнопки
5 / 15 / 30 / 60 минут и «Все»; текущий выбор отмечен галочкой. Например,
`5` — в личку будут приходить только пятиминутные отчёты, `Все` — все
четыре. Настройка хранится в базе (`users.intervals`) и не влияет на другие
каналы. В группах и каналах интервал задаёт админ командой `/channel`.

Что внутри:

- **Bias** — по тренду M5 / M15 / H1 (EMA50 против EMA200): SELL, BUY или
  «нет тренда». Это правило, а не мнение.
- **Зоны** — свинги M5 за окно, сгруппированные по цене. Сила зоны
  считается по касаниям, объёму и свежести: слабая / средняя / сильная /
  сильнейшая. Ближайшая верхняя зона помечается как «точка решения».
- **Свечи и сильные точки** — у каждого интервала свой таймфрейм: 5 минут →
  M5, 15 → M15, 30 → M30, час → H1. Для последних свечей этого ТФ считается,
  сколько раз цена подходила к её хаю и лоу и уходила обратно (касание —
  подход в пределах `touch_tol_points`, отход — `touch_gap_points`).
  Близкие хаи/лоу складываются в точки: уровень, к которому возвращались
  3+ раза, помечается как сильная зона на SELL или BUY.
- **Картинка** — свечи, зоны и последняя цена (Pillow). Если Pillow не
  установлен, отчёт уходит только текстом.

Важно: сила зоны — эвристика, а не проверенная закономерность. Это
информационный разбор, поэтому в сообщении всегда стоит пометка
«Разбор уровней, не сигнал».

Запуск на сервере — `start_hourly.bat` (создаёт окно с `--loop`).

### Итоги дня (01:00 МСК)

Раз в сутки уходит отдельное сообщение — только **сильные и сильнейшие**
зоны дня, с числом касаний и пометкой, что с зоной стало: «отбили» или
«пробили». Уходит **всем** активным каналам, группам и подписчикам,
независимо от их интервалов.

```json
"daily": {
  "enabled": true,
  "time": "01:00",
  "utc_offset": 3,
  "hours": 24,
  "chart": true,
  "per_side": 6
}
```

`utc_offset: 3` — это МСК. Время в `time` задаётся в этом поясе, процесс сам
пересчитывает его в локальное время машины и печатает при старте, когда
следующий отчёт.

`per_side: 6` — сколько зон с каждой стороны вообще рассматривать. В текст
попадают все сильные и сильнейшие из них, так что в хороший день список
может быть длинным.

Проверить вручную:

```bat
python run_hourly.py --once --daily --no-telegram
python run_hourly.py --once --daily --to admin
```

## Канал

Бота можно добавить в канал — туда идёт **только разбор уровней**. Ничего
другого: ни приветствий, ни ответов, ни сигналов.

**Как подключить:**

1. Добавьте бота в канал **администратором** с правом публикации сообщений.
2. В канал при этом ничего не пишется — подтверждение придёт вам в личку.
3. Вся настройка — в личке с ботом. Команд в канале нет.

**Команды (в личке админа):**

| команда | что делает |
|---|---|
| `/channels` | список каналов: id, название, язык, интервалы |
| `/channel <id> ru\|az` | язык анализа в канале |
| `/channel <id> on\|off` | включить или остановить |
| `/channel <id> 5 15 30 60` | какие отчёты слать (5/15/30/60 мин, `all` — все) |

Команда с интервалами **заменяет** набор: `/channel <id> 5 30` — канал будет
получать только 5- и 30-минутные отчёты. Оставить часовой и добавить
пятиминутный — `/channel <id> 5 60`. По умолчанию канал получает раз в час.

- Канал подключается, только если бота добавил сам админ (чат из
  `telegram.chat_id`). Если добавил кто-то другой — вам придёт уведомление,
  доступа у канала не будет.
- Если бота добавили без прав администратора, он предупредит: публиковать
  не сможет.
- Удалили бота из канала — рассылка останавливается автоматически.
- Сигналы в каналы не отправляются, только анализ.

Группы тоже поддерживаются: там язык задаётся командой `/lang` в самой
группе, а сигналы в группы так же не идут.

## Если что-то не работает

- **«Не удалось подключиться к MetaTrader 5»** — терминал не запущен или
  не выполнен вход в счёт. Запустите MT5 и повторите.
- **«Символ XAUUSD не найден»** — добавьте XAUUSD в Market Watch (правая
  кнопка → Show all / Symbols).
- **Мало истории / пустой бэктест** — откройте график XAUUSD M5 в терминале и
  прокрутите его назад, чтобы терминал догрузил историю. Либо увеличьте
  «Max bars in chart» в настройках графиков.
- **Нет сигналов** — проверьте, что сейчас торговая сессия (09:00–15:00,
  12:00–13:00, 12:00–18:00 или 15:00–18:00 по времени сервера) и спред не выше
  лимита. Вне сессий бот молчит.
- **Сигналы пропускаются** — в консоли будет причина: широкий спред, слишком
  далёкий стоп (больше `max_risk_price`), пауза после сделки или лимит на день.
- **«Telegram: включён, но не настроен»** — откройте бота по ссылке из
  раздела про Telegram, нажмите Start и выполните `python telegram_setup.py --wait 120`.
- **Человек не получает сигналы** — проверьте его статус командой `/users`;
  если он «🚫 нет доступа», выдайте доступ: `/allow <id>` или `/allow @username`.
  Если человек не писал боту, добавьте его по числовому ID.
- **«[telegram] сообщение не отправлено»** — проверьте интернет и токен.
  Если токен мог попасть к другим, перевыпустите его у @BotFather.
